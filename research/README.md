# Спринт исследований

Сырьё для тем: `research/<дата>/<направление>.md`. Тема (`topics/`) собирается
только из того, что прошло сверку id; ни один файл здесь темой не является.

Файлы не перезаписываются: каждая волна дописывает раздел `## Заход N` в конец
и правит три строки front-matter. `git diff --numstat` это подтверждает
(`-2` строки, `+N` добавлений).

## Сверка номеров

PMID проверяются через Europe PMC REST (`EXT_ID:<PMID> AND SRC:MED`, `hitCount 1`)
в той же сессии, где попадают в файл, и повторно — сборщиком волны пакетами по 40.
После волны 3: **414 уникальных PMID, все `hitCount 1`**; после волны 4 добавилось
**59 PMID — тоже 59 из 59**; после волны 5 — **40 из 40**. Восемь номеров волн 1–3
пришлись на серию `503`: на это время сверялись через NCBI eutils `esummary`
(названия и годы совпали), после восстановления сервера — Europe PMC.

DOI проверяются по одному через `doi.org/api/handles`, нужен `responseCode 1`.
После волны 3 — **298 из 298**; волна 4 — **59 из 61**, два handle не найдены и
помечены в файлах; волна 5 — **32 из 32**. Два DOI волны 5 пришлось проверять
отдельно: регулярка обрезает адрес на круглой скобке
(`10.1016/s0006-3223(99)00155-9`, `10.1016/s0010-440x(00)90140-8`) — оба дали 1
по полной строке.

Пойманные «по памяти» номера (23621732, 25606708, 17548751, 15085128, 17405996)
оказались чужими статьями и в утверждения не попали — остались в журналах
запросов как пример ловушки.

## Очередь и стопы

Очередь — `research/queue.md`, пополняется в порядке: (а) `next` направлений →
(б) «Не нашёл» в `topics/` → (в) состояний нет в базе → (г) вопросы из тем.
Один пункт — один агент. Пустая очередь — стоп, а не повод выдумывать направление.

Стопы: слово «стоп» или `0Стоп0`; файл `research/.stop` (проверять перед каждой
волной); три волны подряд без новых утверждений; красный `npm run check` или
`node tools/status.mjs`; пустая очередь. Красное — стоп и отчёт, не «починю потом».

Закрытые двери собраны один раз в `research/env-holes.md`; в файлах — строка
«см. env-holes», а не новый пересказ.

## Формат файла направления

```markdown
---
lane: 3
status: сдан | остановлен по времени
next: "с чего продолжать: конкретный запрос или источник"
updated: 2026-11-25
---

## Заход 5 (2026-11-25)
### Что нашёл
- <утверждение одной строкой> — <число>, <год>, <популяция> — <PMID/DOI> — <уровень> — <абстракт/полный текст/вторично>
### Журнал запросов
- Europe PMC — `<дословная строка>` — вернулось 12, отобрано 4
### Где расхождения
### Не открылось
### Не нашёл
```

`status: сдан` — только когда `next` пуст; иначе `остановлен по времени`.

## Экономия волны

- Агент читает front-matter и хвост файла (последние ~120 строк), тело не листает.
- Одно утверждение — одна строка `- `, до 240 знаков; абзацы — только в «Не нашёл».
- Перед запросом — grep по «Журнал запросов», перед записью — grep по id.
- Кап: 60 утверждений и 25 КБ прироста на файл за волну.
- TSV не пишется руками: `node tools/research-stats.mjs --tsv claims.tsv`.
