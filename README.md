# Пси-база

Общедоступная база знаний о психических расстройствах: что известно, насколько
это доказано и чего мы пока не знаем. Собирается из исследований, а не из
мнений и не из пересказов.

> База не заменяет врача, не ставит диагноз и не назначает лечение.
> Если жизни или здоровью угрожает опасность — **112**.

Сайт: <https://testsoulja.github.io/psybase/> — тот же текст, собранный из
`topics/`. Вход один, без выбора роли: для человека с диагнозом, его близких,
студента, врача и журналиста текст один и тот же.

Утверждение здесь стоит ровно столько, сколько стоит источник под ним: у каждого
числа назван тип исследования, у каждой темы есть раздел о том, чего не хватает.

Базу ведёт TestSoulja; это личный проект, не клиника и не медицинская организация.

English summary: [`README.en.md`](README.en.md).

Числа в таблице печатает `node tools/status.mjs` — он же падает, если таблица
разойдётся с `topics/` и с `sources:` в каждой теме.

Русский — канон: тема существует, когда есть `ru.md`. Английский — перевод там,
где он сделан; тема без `en.md` публикуется по-русски, а `/en/<slug>/` — страница-
маршрут с `canonical` на русскую. В карточке источника помечается язык оригинала:
английские числа нельзя переносить на русские формулировки как на эквивалент.

**Что внутри темы — минимум разделов**, а не жёсткий список: тема может добавлять
свои. Обязательный минимум: «Что это», «Что не доказано», «Не нашёл»,
«Источники» — его проверяет `node tools/status.mjs`. «Что известно» в минимум не
входит: там, где текст идёт по вопросам (ПРЛ, «Депрессия и ПРЛ», биполярное
расстройство), его роль играют собственные разделы, а пустой контейнер хуже
отсутствующего. Сверх минимума, например, у ПРЛ есть «Как часто», «Чем это
не депрессия, не биполярное, не ПТСР и не СДВГ», «Суицид и самоповреждение»,
«Течение», «Что помогает» и «Близкие».

## Как проверить утверждение

Три шага на настоящем числе — смертность при ПРЛ.

1. **Число.** В теме ПРЛ: «смертность от суицида в 29 раз выше общей популяции —
   SMR 29,0».
2. **Уровень доказательности.** Рядом стоит бейдж `cohort`: это когортное
   наблюдение, а не эксперимент и не мета-анализ. Другое исследование того же
   вопроса могло бы дать другую цифру — и тогда в теме стояли бы обе.
3. **Карточка источника.** Ссылка ведёт в `sources/williams-2026-mortality.md`:
   PMID 42954355, DOI 10.1177/00048674261498135, 10 059 человек, 13 лет, 216
   суицидов. PMID и DOI открываются по своим адресам — сравните число там, а не
   здесь.

Если карточка говорит «полный текст не открыт», это записано и в теме: то, чего
не видели, не пересказывается по памяти. Источники, которые не открылись,
перечислены в разделе «Не нашёл» с причиной.

## Как читать график

График в теме — не украшение, а те же числа, что стоят в тексте, поставленные на
одну ось.

- **База бара.** В блоке графика поле `bases` говорит, от чего считается доля.
  Сейчас у баров воронки одно значение — `all`, все случаи. Один график — один
  знаменатель: если сложить на одной оси долю от всех и долю от подгруппы,
  картинка соврёт.
- **Единица.** Поле `unit` ставит «%» и к значениям, и к делениям оси. Число без
  единицы на графике — ошибка, а не экономия места: «50» может быть процентом,
  человеком и годом.
- **Примечание `note`.** Условная доля — например, 41,9 % получивших лечение,
  у которых лечение было адекватным, — столбиком не рисуется: она считалась от
  другой базы и на общей оси заняла бы чужое место. Она стоит подписью под
  графиком и строкой в таблице-эквиваленте, с указанием, от чего считается.

Под каждым графиком есть таблица с теми же числами: она нужна печати, экрану без
CSS и чтению с экрана. Оба собираются из одного блока `chart` в
`tools/build.mjs`, поэтому разойтись не могут; `npm run check` сверяет пару
RU/EN, а не график с таблицей.

## Типы исследований (и почему это не GRADE)

Тип — это дизайн исследования, а не оценка качества: `meta` не значит
«доказано», а `case` — «неправда». Почему база не считает GRADE и что означает
пометка рядом с числом — на странице
[«Как мы оцениваем доказательства»](https://testsoulja.github.io/psybase/ru/dokazatelnost/).

| Тип | Что за ним стоит |
|---|---|
| `meta` | систематический обзор, мета-анализ |
| `rct` | рандомизированное контролируемое исследование |
| `cohort` | когорта, наблюдение, случай-контроль |
| `review` | обзор без метаанализа, консенсус, гайд |
| `case` | описание случая или серии случаев |
| `opinion` | экспертное мнение, редакционная статья |
| `unsure` | тип определить не удалось — и это видно читателю |

Если тип определить нельзя, это пишется прямо, а не прячется: ровный тон без
типа и есть то, что делает базу опасной.

## Чего здесь нет и не будет

- диагностики и «проверь себя» с подсчётом баллов;
- советов «что делать именно вам» и лечебных обещаний;
- рейтингов «какое лекарство лучше»;
- перепечатанных абстрактов: факт формулируется своими словами, ссылка ведёт
  на источник;
- пересказа источников, которые не удалось открыть;
- личных историй и разбора случаев из переписки.

## Как это делается

Четыре правила, без которых это не база:

1. пункт без источника — не пункт: источник открыт, PMID/DOI сверен, а не взят
   по памяти;
2. у каждого числа — уровень доказательности;
3. расхождения показываются, а не сглаживаются: два источника дали разные
   числа — в тексте оба, с объяснением разницы;
4. раздел «Не нашёл» обязателен и не может быть пустым: пустой поиск — тоже
   результат.

Плюс два правила языка, которые появились из разбора ошибок:

- определение термина берётся из методов статьи, а не из аннотации;
- если аннотация и методы расходятся, приводятся оба, а не выбирается молча.

Подробно: [`docs/rules.md`](docs/rules.md) — правила приёма,
[`docs/style.md`](docs/style.md) — язык, [`docs/schema.md`](docs/schema.md) —
схема карточек и графиков. Что в этой среде не открывается —
[`docs/env.md`](docs/env.md).

## Как добавить тему

1. Открыть источники и сверить PMID/DOI — не по памяти: PMID, взятый на память,
   уже дважды оказывался чужой статьёй.
2. Завести карточки в `sources/`: `id`/`doi`, `lang`, `type`, `read`
   (`abstract` | `full` | `page` | `unknown`), `year`, `taken`, `accessed` по
   [`docs/schema.md`](docs/schema.md).
3. Написать `topics/<slug>/ru.md` (и `en.md`, если перевод есть) — с минимумом
   разделов и числом `sources:` во front-matter.
4. Заполнить «Не нашёл»: пустым он быть не может, недоступный источник — тоже
   запись.
5. Прогнать `node tools/status.mjs`, `node tools/parity.mjs` и
   `node tools/build.mjs` — или сразу `npm run check` и сборку; таблица тем в
   этом README тоже должна пополниться, иначе `status.mjs` упадёт.

## Как добавить страницу

1. Папка `pages/<slug>/ru.md` — страница собирается в `/ru/<slug>/`.
2. `slug` во front-matter = имя папки; только `a-z`, `0-9`, дефис.
3. `title` во front-matter обязателен — он идёт в `<h1>` и в «Ещё о базе».
4. `en.md` у страницы запрещён: страницы каталога пока только RU, сборка упадёт.
5. Темой не считается: в «Тем: N» и в сноску карточек не входит.

## Нашли ошибку

Issue в этом репозитории — про текст и источники. Полезно указать:

- тему и точную цитату (или адрес страницы);
- что не так: число не сходится с источником, ссылка не открывается, PMID/DOI
  ведёт не туда, утверждение звучит как обещание лечения, формулировка
  стигматизирует при верном факте;
- если не сходится число — что именно сказано в источнике и где это видно.

Правим текст, а не спорим: факт важнее тона, но и тон — часть факта.

## Предложить тему или источник

Отдельный Issue — с пометкой «тема» или «источник». Для темы: о каком
расстройстве или вопросе речь и почему его в базе не хватает. Для источника:
название, PMID или DOI, язык оригинала и что из него можно взять.

Предложения не обещают сроков: тема появляется, когда для неё есть проверенные
источники, а не когда она названа.

Это не канал поддержки: личные истории и вопросы «что со мной» здесь не
разбирают, и отвечаем не сразу. Если плохо прямо сейчас — 112, а не Issue;
в неэкстренном случае — служба психологической помощи в вашем регионе.

обновления темы печатает сама страница — берите её оттуда, а не из этого файла.

## Для тех, кто ведёт базу

| Каталог | Что лежит |
|---|---|
| `sources/` | карточки источников: PMID/DOI, язык оригинала, тип исследования, что именно взято; на сайте — индекс `/psybase/ru/istochniki/` и страница на каждую карточку |
| `topics/` | темы: `ru.md` обязателен, `en.md` — перевод рядом |
| `pages/` | каталог: отдельные страницы (`ru.md` с `slug`/`title`/`updated`) со своим адресом `/ru/<slug>/`; в число тем и сноску карточек не входят |
| `for-app/` | следствия для приложения «Опора», на сайт не публикуется |
| `research/` | поиск по датам: `queue.md` (очередь запросов), `README.md`, `env-holes.md` и папки по датам — найденное и пустые поиски |
| `legacy/` | прежний корпус как был (`opora/`, `inbox/`, `archive/`); не переписывается, темы переезжают оттуда в `topics/` |
| `docs/` | `concept.md` (что это за база), правила приёма, схема данных и графиков, язык, среда |
| `tools/` | проверки и сборка без зависимостей: `parity.mjs`, `status.mjs`, `build.mjs` |
| `scripts/` | `deploy-pages.ps1` — выкладка `dist/` в `gh-pages` |
| `LICENSES/` | тексты лицензий и что под какой |
| `dist/` | собранный сайт; в git не попадает, публикуется только он |

Зависимостей нет: проверено на Node 26.13 (для выкладки — ещё PowerShell).

```bash
npm run check                      # parity.mjs + status.mjs
node tools/parity.mjs depressiya   # одна тема по слагу
node tools/status.mjs              # темы, число источников, долг перевода, README
node tools/build.mjs               # dist/ — те же 4 темы, /ru/<slug>/ и /en/<slug>/
node tools/build.mjs --fixture     # только topics/_example, во временную папку
scripts/deploy-pages.ps1           # выкладка в gh-pages — по слову владельца
```

`parity.mjs` сверяет пару RU/EN по тому, что не зависит от языка: заголовки,
числа, PMID, DOI, ссылки, блоки графиков и `note`. Стиль он не проверяет — это
делает человек по `docs/style.md`.

### Сборка сайта и выкладка

`node tools/build.mjs` собирает `dist/`: `/ru/<slug>/` у всех тем, `/en/<slug>/` —
перевод или страница-маршрут. Адрес задаётся одной константой `BASE` в
`tools/build.mjs`; локально открывать `dist/index.html` напрямую нельзя — ссылки
абсолютные, нужен статический сервер с этим префиксом.

В `dist/` попадают только темы из `topics/`. Темы с `draft: true` пропускаются,
и в логе сборки написано, что именно пропущено. На каждой странице — дисклеймер
«не заменяет врача» и 112, дата обновления, уровни бейджами, блок «Не нашёл» и
источники со ссылками на PMID/DOI. Markdown экранируется целиком, сырой HTML не
проходит. Нет раздела «Не нашёл» — сборка падает.

В ветке `gh-pages` лежит только содержимое `dist/` плюс `.nojekyll`; история
только дописывается, force-push запрещён. `scripts/deploy-pages.ps1` требует
чистое дерево, `npm run check` с exit 0 и успешную сборку, а если ветка ушла
вперёд — падает, а не переписывает.

Где остановились — [`STATUS.md`](STATUS.md), читается первым: что сделано, что
дальше и какие поиски закончились пусто.
